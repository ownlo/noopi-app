# 누피 캐릭터 인사 스플래시

> 이전 버전 기록입니다. v0.1.0+12부터 애니메이션을 제거하고 [원형 테이블 정적 이미지](splash-round-table.md)로 교체했습니다.

누피·우피는 왼쪽에서, 당비는 오른쪽에서 화면 중앙으로 걸어와 손을 흔듭니다.
이미지 디코딩이 끝난 뒤 5.2초 타임라인을 시작하며, 웹 준비와 애니메이션 완료가
모두 확인된 다음 220ms 페이드로 웹 화면을 표시합니다.

## 리소스와 생성

`assets/splash/greeting/{noopi,woopi,dangbi}.png`는 각각 1536×1024 RGBA 아틀라스입니다.
기존 캐릭터 이미지를 참조해 내장 `image_gen` 도구로 캐릭터마다 따로 생성했습니다.
원본 알파를 보존했으며, 모서리 픽셀의 알파가 0임을 확인했습니다.
정확한 생성 프롬프트와 참조는 [splash-greeting-prompts.json](splash-greeting-prompts.json)에 있습니다.

각 아틀라스의 윗줄은 몸통/머리·왼팔·오른팔, 아랫줄은 왼다리·오른다리·꼬리입니다.
`rigs.json`은 각 부위의 소스 영역을 기록합니다. 생성 이미지의 실제 부위 위치를
읽는 `dart run tool/generate_splash_rigs.dart`로 다시 만들 수 있습니다.
PNG를 자르거나 배경을 편집하지 않고 소스 사각형만 계산합니다.

## 움직임

- 0–2.7초: 캐릭터마다 출발 시간을 다르게 하고 중앙까지 이동합니다.
  이동 거리와 보폭을 연결해 다리 교차, 발 들어 올리기, 반대 팔 움직임과 몸의 흔들림을 맞춥니다.
- 2.65–5초: 도착한 캐릭터가 팔을 들어 반복해서 흔든 다음 자연스럽게 내립니다.
- 5.2초: 완료 콜백을 한 번만 보냅니다. 웹 로딩이 남았으면 중앙에서 호흡과 꼬리 움직임을 유지합니다.
  이 상태에서 화면을 탭하면 다시 인사합니다.

Flutter `AnimationController`와 Canvas의 연속 관절 변환으로 화면 갱신마다 보간합니다.
프레임별 PNG 전환이나 GIF 재생을 사용하지 않습니다. 아틀라스는 한 번 디코딩하고
위젯 종료 시 해제합니다. 움직이는 영역은 RepaintBoundary로 격리합니다.
네이티브 시작 화면과 같은 `#101426` 배경을 유지합니다.

동작 줄이기 설정에서는 정지한 세 캐릭터를 보여주고 인사 대기를 생략합니다.
리소스 로딩 실패 시 기존 놀이 그림으로 대체하고 완료를 알려 무한 대기를 피합니다.
최초 연결 실패 후 재시도하면 새 인사를 재생하며, 이전 인사의 늦은 콜백은 무시합니다.
웹 연결의 25초 타임아웃은 애니메이션 대기와 별개로 관리합니다.

## 검증

정적 분석과 테스트 16개 통과: 세 화면 크기, 인사 완료/중복 콜백, 동작 줄이기,
리소스 로딩 도중 종료, 빠른 웹/느린 웹, 최초 재시도, 타임아웃 및 기존 링크 정책.
Flutter 렌더러에서 전체 타임라인을 100ms 간격으로 캡처해 관절과 인사 포즈를 확인했습니다.
`build/noopi-splash-preview.gif`는 이 캡처를 합친 미리보기이며 앱 재생 리소스가 아닙니다.
실제 Android/iOS 기기의 프레임률은 아직 측정하지 않았습니다.
